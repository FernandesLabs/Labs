# Search performance analysis — 29 October 2026

Source: `fernandeslabs.com-Performance-on-Search-2026-10-29.zip`, Web search,
28 July–27 October 2026. Full tables: [generated report](gsc-2026-10-29.md).

## What the export shows

The site earned **38 clicks from 9,154 impressions (0.42% CTR)**. Its
impression-weighted average position was **73.26**, so most visibility is
still far from the first results. Improving snippets alone will not address
the main ranking gap.

| Equal-length period | Clicks | Impressions | CTR | Average position |
|---|---:|---:|---:|---:|
| 2–29 September | 3 | 398 | 0.75% | 43.57 |
| 30 September–27 October | 29 | 2,562 | 1.13% | 56.98 |

Recent visibility and clicks grew, while average position worsened. Changes
in the mix of queries can move that average. These data do not show which
edits caused the growth. Counts are small, so percentage changes are noisy.

The earlier export covers 22 July–21 October, a different rolling window.
Comparing its 9,892 impressions directly with 9,154 would incorrectly suggest
a current decline: the new window drops six July days and adds six October
days. The added 22–27 October dates contributed 9 clicks and 834 impressions.

### Font readability: protect the main source of clicks

The font page contributes 84.2% of site clicks. The sampled query “font
readability test” has 89 impressions, no clicks and position 2.52; “font
accessibility checker” has 42 impressions and 5 clicks. This suggests testing
clearer readability wording, but does not prove a snippet mismatch: the export
has no query-to-page or query-to-device join.

The title now starts with “Font Readability Test”, while retaining “Font
Accessibility Checker”. The homepage uses the same language. The summary
explains the preview and measurements without promising WCAG conformance.
Relevant links connect this tool, the contrast checker, ARIA validator and
reading-time calculator.

The tool now measures text fragments rather than counting paragraph boxes as
extra lines, and remeasures after resizing or fonts loading. Its score is
explicitly a typography checklist. The matching tool content and guide
correct claims about a mandatory 16px WCAG minimum and default line spacing.
The guide directs readers to the separate contrast tool and real resize,
spacing and reflow checks, with W3C references.

### IP lookup: fix the result before optimizing its promise

The tool has the most page impressions but only two clicks. The previous
empty-input request called the provider without a target IP from the server,
which geolocated the server's outbound connection. It now explicitly uses the
visitor address supplied by the deployment proxy. If that is unavailable,
the tool asks for an address rather than showing the server's location.

Hostnames now resolve before the IP-only geolocation request, and validated
IPv4 and IPv6 literals are supported. Isolated tests cover these paths,
malformed input, missing headers, DNS failures and upstream failures. The
metadata, examples and guide describe the explicit “Use my IP” action rather
than promising automatic lookup on page load. Examples no longer present
fixed city locations for anycast resolvers as guaranteed output.

### Robots.txt: useful Google guidance on the existing URL

The sampled robots cluster has 1,171 impressions and no clicks, including
“robot txt generator google”, “robot txt maker” and “make robots txt online”.
The page already targets those terms; another spelling-based page would
duplicate its intent.

The updated copy explains a Googlebot-specific group, custom wildcard rules,
which group applies, publishing at `/robots.txt`, and checking the deployed
file. It distinguishes crawl restrictions from indexing and authentication,
removes contradictory Disallow-plus-noindex advice, and corrects obsolete
testing and file-size instructions. The generator does not claim to fetch or
validate the live site.

### Page delivery: stop bundling every tool's copy

Client components previously imported a map containing all 132 tools'
editorial content, roughly 926 KB of TypeScript source. The server route now
resolves just the current tool's content and passes that object through to
the visible text and JSON-LD. This removes the full editorial map from the
client dependency graph. Source size is not a measured transfer saving or
a Core Web Vitals result.

Regression checks render the real content and schema for every tool and
verify all FAQs and how-to steps match. A dependency-graph check prevents the
all-tool content map from returning to the client. Existing canonical URLs,
routes and crawlable navigation are retained. Sitemap timestamps change for
the pages substantively revised, rather than making every URL look fresh.

The build originally depended on downloading Geist fonts from Google Fonts.
It now uses the installed Geist package's two variable WOFF2 files through
`next/font/local`, retaining the existing CSS font variables and swap behavior.
This removes that build-time network dependency without adding a package.

## Limits of this analysis

- The query table contains 1,000 rows and only 6 of the 38 site clicks.
  Omitted and anonymized queries prevent complete keyword attribution.
- Page impressions total 9,256; the chart totals 9,154. These use different
  aggregation levels and should not be added together or treated as equal.
- The export includes no indexing coverage, crawl logs, Core Web Vitals,
  backlinks, conversions or query-by-page breakdown. Ninety-five pages with
  impressions does not mean the other pages are unindexed.
- A web fetch of the font page returned older generic copy. Because that
  fetch may be cached, it cannot establish the currently deployed revision.
  Deployment and URL Inspection are the checks that establish what Google
  can now see.

## Deployment and measurement

The changes are prepared locally. After deployment:

1. Inspect the font, IP and robots tool URLs plus their revised guides in
   Search Console. Check the selected canonical and rendered content, then
   request indexing for those changed URLs.
2. Verify “Use my IP” against the deployment's forwarded visitor address and
   confirm that hostname and IPv6 lookups work with the live provider.
3. Compare 28 complete days after deployment with the preceding 28 days.
   Use page-filtered query and device reports, particularly font readability
   versus font accessibility searches. Track clicks and impressions alongside
   CTR and position, allowing for query-mix changes.
4. Measure real loading and interaction with PageSpeed Insights and field
   Core Web Vitals when sufficient traffic exists. Do not infer an LCP/INP
   improvement from the import-graph change alone.
5. If high-impression URLs remain deep in results, use the indexing report
   and query-by-page evidence to investigate eligibility, intent and content
   usefulness before making another title rewrite.

Google may rewrite titles and snippets and needs to recrawl changes. These
improvements address concrete defects and intent gaps; rankings remain an
outcome to measure.

## Validation completed locally

- `bun test`: 131 passing tests, including all 132 tools' visible FAQs and
  matching JSON-LD, IP target/error cases, content delivery and report windows.
- `bun run lint`, `bun run typecheck`, and `bun run build`: passed. The build
  required normal local process permissions because sandboxed Turbopack could
  not bind its internal CSS compiler port.
- Generated HTML: all 132 tool pages have exactly one correct canonical,
  titles at most 62 characters, descriptions at most 160 characters, and
  crawlable related-tool links. The homepage links to all 132 tools.
- Generated pages preload exactly two local variable fonts; both assets are
  included in the production output.
- Production browser check: the font tool preview renders and responds.
  Resizing from the desktop viewport to 390px changes the measured
  line length from approximately 86 to 25 characters per line, confirming
  resize-driven measurement. The mobile document has no horizontal overflow.

The local feedback-statistics endpoint reported a missing `ToolFeedback`
database table during this browser check. No database migration was applied;
the preview and SEO checks above passed independently of that optional widget.

Live provider behavior, deployment proxy configuration and search ranking
changes still need the post-deployment checks above.
